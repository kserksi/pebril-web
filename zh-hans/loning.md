## 01. 设计目标

### 1.1 模块定位

Prelude 是 Pebril 官网相册扉页之前的品牌序章，同时承担资源加载过渡界面的职责。

其核心目标包括：

1. 避免首屏关键资源未就绪时，用户看到元素缺失或尚未完成布局的网页。
2. 将实际资源加载进度转化为同心圆的涟漪变化，使等待过程具有直观的视觉反馈。
3. 通过简洁且连续的动画建立 Pebril 的品牌印象。
4. 在稳定状态下，通过轻微呼吸和输入响应维持界面的生命感。
5. 通过同心圆向单一直线的形态转变，为第二屏「时间漫游」中的时间轴建立视觉伏笔。
6. 确保所有动画与用户滚动行为自然衔接。

### 1.2 核心设计理念

**Quietly Present. — 静静存在，恰如其分。**

Prelude 不应成为高强度的动画表演。

整个模块遵循以下原则：

- 安静而不沉闷。
- 有生命力而不过度活跃。
- 运动连续、自然，避免明显的机械感。
- 资源加载进度必须具有真实的技术依据。
- 自主动画不能干扰用户主动交互。
- 视觉状态之间保持连续性。
- 加载失败时不应阻止用户进入网站。

### 1.3 设计叙事

**浮现 → 涟漪平息 → 品牌交替 → 平静呼吸 → 圆环展开 → 汇聚成线 → 品牌归位。**

其中，「涟漪平息」反映资源加载过程，「平静呼吸」属于加载完成后的稳定状态。

两者具有不同的交互意义，不能混为同一种动画。

## 02. 静态视觉规范

### 2.1 画布与构图

桌面端以用户提供的 PPT 原型图为视觉基准。

采用中央轴线构图。

主要视觉元素包括：

- 暖白色背景。
- 三个共享圆心的同心圆。
- 位于圆心的品牌文字。
- 不使用额外的显著装饰元素。

首屏照片河流与时间轴交互控件不在 Prelude 初始状态中出现。

### 2.2 同心圆

三个圆环分别命名为：

- Ring I — 内圈
- Ring II — 中圈
- Ring III — 外圈

三个圆环共享相同的圆心。

以 PPT 构图为参考，三个圆环的初始半径比例约为：

**内圈 : 中圈 : 外圈 = 0.56 : 0.78 : 1**

精确比例需在原型中确认。

圆环采用细线描边，不使用实心填充。

加载阶段允许圆环轮廓发生轻微波动，但必须保留整体同心结构。

### 2.3 品牌文字

中心包含两个独立文字图层：

**Pebril**

**溪石**

字体沿用现有品牌规范：

| 元素 | 字体 |
|---|---|
| Pebril | Manrope |
| 溪石 | 霞鹜文楷 |

两个文字图层共享视觉中心，但不要求具有相同的文字宽度。

### 2.4 颜色

| 元素 | 参考值 |
|---|---|
| 背景 | `#F8F7F3` |
| 品牌文字 | `#59666C` |
| 圆环 | 低对比度中性灰 |
| 辅助强调 | `#526B79` |

涟漪效果优先通过圆环轮廓的微弱变化表达，不依赖强烈的色彩变化。

## 03. 动画生命周期

Prelude 分为四种主要状态。

| 状态 | 动画 | 触发条件 |
|---|---|---|
| Loading · 加载中 | P0 + Loading Ripple | 最小启动资源就绪，首屏资源持续加载 |
| Entering · 进入 | P1 | 首屏关键资源全部就绪，涟漪平息 |
| Idle · 稳定 | P2 + P3 | P1 完成 |
| Exiting · 退出 | P4 + P5 | 用户主动向下滚动 |

### 3.1 运行顺序

1. 浏览器打开 Pebril 官网。
2. 最小启动资源准备完成。
3. P0 开始播放，同心圆与 Pebril 浮现。
4. 其他首屏关键资源继续加载，同心圆以涟漪强度反映加载进度。
5. 随着进度提高，涟漪逐渐平息。
6. 首屏关键资源准备完成，进入 P1。
7. Pebril 渐隐，「溪石」渐显。
8. 进入 P2、P3 的持续稳定状态。
9. 用户向下滚动，触发 P4、P5。
10. 同心圆归为单一直线并退场，Pebril 移动至导航栏中央。
11. 正式相册扉页进入主要可见状态。

### 3.2 状态管理原则

每种状态必须具有清晰的进入条件和退出条件。

P0 的显现动画与 Loading Ripple 可以部分重叠。

P2 与 P3 并行运行。

P4 与 P5 共用同一滚动进度。

所有状态切换应避免突然跳变。

## 04. Loading Ripple — 加载进度涟漪

**新增模块**

本模块定义资源加载进度与同心圆视觉波动之间的关系。

### 4.1 核心设计定义

资源加载进度越低，同心圆的涟漪越明显。

随着资源逐渐加载完成，圆环的波动幅度持续减小。

当首屏关键资源准备完成时，涟漪完全平息，三个圆环恢复为规则、平静的同心圆。

**加载进度越高，涟漪越趋近于平静。**

这是 Loading Ripple 的核心设计规则。

### 4.2 涟漪的表现形式

加载期间，同心圆的半径并非完全固定。

圆环轮廓允许出现幅度有限、连续传播的柔和波动。

具体表现为：

- 圆环保持整体圆形结构。
- 局部轮廓可以沿径向产生微弱位移。
- 波动平滑传播，不出现尖锐折角。
- 不产生明显的旋涡、碎裂或剧烈扭曲。
- 不改变三个圆环的基本层级关系。

涟漪应更接近水面上的轻微扰动，而不是抽象的音频频谱图。

### 4.3 加载进度与涟漪强度

定义：

- `P`：首屏关键资源加载完成比例，范围为 0–1。
- `Amax`：允许的最大涟漪振幅。
- `A(P)`：当前目标涟漪振幅。

建议第一轮采用非线性衰减关系：

**A(P) = Amax × (1 − P)^1.35**

该公式仅作为第一轮实验方案。

其设计意图是：

加载初期具有适度可见的涟漪。

随着加载进度提高，波动逐渐减弱。

接近完成时，涟漪已基本趋于平静。

加载完成时，振幅为零。

### 4.4 参考强度

| 加载进度 | 相对涟漪强度 |
|---|---|
| 0% | 100% |
| 10% | 约 87% |
| 25% | 约 67% |
| 50% | 约 39% |
| 75% | 约 15% |
| 90% | 约 4% |
| 100% | 0% |

表中的涟漪强度是相对于 `Amax` 的比例，并非圆环半径变化百分比。

最大实际振幅需要通过原型验证。

### 4.5 进度平滑

实际资源加载进度可能发生不均匀变化。

例如：

- 多张照片连续加载完成。
- 某个字体资源延迟加载。
- 某个初始化任务突然完成。

不得直接将这些离散事件转化为突兀的圆环变形。

系统应区分：

**实际加载进度（Actual Progress）**

**视觉显示进度（Visual Progress）**

视觉进度应平滑追随实际进度，避免圆环振幅突然改变。

视觉进度不得超前于实际确认完成的进度。

达到 100% 时，圆环应平滑恢复为规则圆形，而不是突然停止运动。

### 4.6 涟漪与圆环颜色

加载阶段的主要变化应由几何波动幅度体现。

圆环颜色保持总体稳定。

如果需要增加颜色变化，只允许非常轻微的透明度变化。

不能让颜色闪烁成为加载状态的主要反馈方式。

### 4.7 加载结束

当首屏关键资源全部准备完成：

1. 实际加载进度达到 100%。
2. 涟漪振幅平滑衰减至零。
3. 三个圆环恢复为完整同心圆。
4. 系统触发 P1 品牌文字交替动画。

建议在涟漪平息和 P1 开始之间保留极短且自然的视觉过渡。

不设置为了展示动画而强制延长的等待时间。

## 05. P0 — Initial Appearance

**初次显现**

### 5.1 触发条件

最小启动资源准备完成。

这里的最小启动资源包括：

- Prelude 基础 HTML 与 CSS。
- 同心圆的 SVG 或等效渲染资源。
- 最小动画控制逻辑。
- 可用于显示品牌名称的字体或可靠回退字体。

P0 不需要等待全部首屏照片加载完毕。

### 5.2 动画行为

三个同心圆与 Pebril 在原始位置同步浮现。

初始透明度为 0，逐渐提高至正常状态。

不执行显著位移、旋转或缩放。

### 5.3 时间要求

**约 1 秒。**

### 5.4 与 Loading Ripple 的关系

P0 可以与资源加载过程重叠。

随着 P0 的透明度增加，用户逐渐看见当前加载进度对应的涟漪状态。

Loading Ripple 的波动幅度由资源进度决定，而不是由 P0 的播放时间决定。

### 5.5 快速加载情况

如果关键资源在 Prelude 显现前已经完成加载，可以直接展示平静圆环并进入品牌交替。

不得为了展示加载涟漪而人为降低进度或增加等待。

## 06. P1 — Brand Alternation

**品牌文字交替**

### 6.1 触发条件

同时满足：

- P0 已完成或已安全结束。
- 首屏关键资源准备完成。
- Loading Ripple 已恢复平静。

### 6.2 动画行为

中心文字由 Pebril 转变为「溪石」。

Pebril 开始降低透明度。

「溪石」同步开始增加透明度。

两个文字图层的渐隐和渐显存在时间重叠。

### 6.3 时间要求

**约 1 秒。**

### 6.4 结束状态

- Pebril 完全隐藏。
- 「溪石」完整显示。
- 三个同心圆保持完整。
- 系统进入 Idle 状态。

### 6.5 设计限制

两个文字图层必须保持中心稳定。

不得突然替换文本或产生明显布局偏移。

---

## 07. P2 — Ripple Interaction

**交互涟漪**

### 7.1 触发条件

P1 完成，系统进入 Idle 状态。

### 7.2 动画行为

同心圆可以响应用户输入，产生轻微涟漪反馈。

交互形式可包括：

- 鼠标靠近或移动。
- 鼠标点击。
- 触摸输入。

具体触发条件和交互区域由原型验证决定。

### 7.3 与 Loading Ripple 的区别

Loading Ripple 的振幅由资源加载进度控制。

P2 的涟漪由用户输入触发。

**加载涟漪与交互涟漪是两个独立的逻辑模块。**

P2 不应继续读取加载进度作为波动来源。

### 7.4 交互限制

用户输入产生的反馈应快速、柔和地衰减。

不得无限累积振幅。

不得影响后续滚动退出动画。

交互反馈的设计语言参考白皮书 Phase 5 · Quiet Closure 中的轻微扰动原则。

---

## 08. P3 — Breathing Rings

**同心圆呼吸**

### 8.1 触发条件

与 P2 同时进入稳定状态。

### 8.2 动画行为

三个规则同心圆进行缓慢扩张与收缩。

扩张时：

- 圆环半径逐渐增加。
- 颜色或透明度轻微变淡。

收缩时：

- 圆环半径逐渐恢复。
- 颜色或透明度恢复初始状态。

### 8.3 建议参数

| 参数 | 第一轮建议 |
|---|---|
| 呼吸周期 | 5–7 秒 |
| 半径变化 | 约 ±1%–2% |
| 缓动 | 柔和、周期连续 |
| 相位差 | 微小或同步，待验证 |
| 循环 | 连续，无跳变 |

### 8.4 与加载状态的区别

Loading Ripple 是不规则轮廓扰动逐渐消失。

P3 是规则圆环整体半径的缓慢周期变化。

两者不能表现为完全相同的动画效果。

### 8.5 与交互涟漪的关系

P2 可以在 P3 的基础上叠加轻微扰动。

主动输入优先于自主呼吸。

进入 P4 时，P2 和 P3 均需平滑让位。

## 09. P4 — Circle to Line

**同心圆归线**

### 9.1 触发条件

用户主动向下滚动。

动画进度由用户滚动位置决定。

### 9.2 核心定义

**三个同心圆从外圈到内圈依次在顶部断开，沿连续轨迹展开，最终汇聚为唯一一条水平直线。**

最终不是三条平行线。

也不是三个圆分别消失后再生成新线条。

### 9.3 动画分解

**Step A — 顶部断开**

最外圈首先在顶部断开。

中圈随后断开。

内圈最后断开。

三个动作可存在少量时间重叠。

**Step B — 圆环展开**

断开的圆环沿连续曲线逐渐展开。

保留可感知的形态转换过程。

不采用瞬间形态替换。

**Step C — 三环归一**

展开后的三个圆环逐渐靠近共同的水平基准线。

最终形成一条完整的水平直线。

该过程应保留视觉连续性，不出现突然消失、重复线条闪烁等问题。

**Step D — 线条退场**

统一的水平线向画面下方移动。

移动过程中，透明度逐渐降低。

最终完全离开主要视觉区域。

### 9.4 与时间轴的关系

本阶段形成的水平线是第二屏「时间漫游」中时间轴的视觉伏笔。

Prelude 的线条代表从涟漪到秩序的变化。

第二屏重新显现的时间轴则具有实际的时间刻度与交互功能。

两者在设计语言上连续，但不必由同一个图形元素贯穿所有场景。

### 9.5 技术方向

建议使用 SVG 路径变形等能够精确控制曲线的方法。

GSAP 可用于管理滚动进度、透明度、位置及状态变化。

具体展开算法需单独制作技术验证原型。

## 10. P5 — Brand Transition

**品牌归位**

### 10.1 触发条件

与 P4 同步触发。

使用同一个滚动进度。

### 10.2 动画行为

中心文字「溪石」逐渐隐藏。

Pebril 重新显现，并逐渐移动到导航栏中央位置。

### 10.3 结束状态

- 「溪石」完全隐藏。
- Pebril 位于顶部导航栏中央。
- 同心圆完成归线和退场。
- 相册扉页成为主要可见场景。

### 10.4 设计约束

品牌文字的位置变化应连续。

字体大小允许平滑调整，以适应导航栏布局。

不得突然替换文字节点造成视觉跳变。

P4 和 P5 必须保持统一的滚动控制逻辑。

## 11. 滚动行为规范

### 11.1 基本要求

P4、P5 由滚动进度控制。

用户停止滚动时，画面应稳定在当前状态。

用户向上滚动时，应支持反向恢复。

### 11.2 反向过程

P4 反向恢复：

水平线重新展开为弧线，再逐渐恢复三个完整同心圆。

P5 反向恢复：

Pebril 从导航栏方向返回中心过渡区域并渐隐，「溪石」重新显现。

最终恢复 Idle 状态。

### 11.3 加载期间的滚动

由于 Loading Ripple 需要在加载过程中保持可见，加载期间的滚动处理必须避免进入尚未准备好的页面。

建议在 Loading 状态下暂不允许触发 P4、P5，但不应造成永久滚动锁定。

关键资源就绪、品牌进入流程完成后，恢复正常滚动控制。

具体操作方案与提前滚动输入的处理仍需原型验证。

### 11.4 多种输入方式

需要覆盖：

- 鼠标滚轮。
- 触控板。
- 触摸滚动。
- 键盘滚动操作。

不得仅依赖鼠标 Hover 完成页面导航。

## 12. 资源加载与技术规范

### 12.1 资源分级

**启动资源（Bootstrap）**

负责尽快显示 Prelude 的基本构图及加载反馈。

**首屏关键资源（Critical）**

包括首屏需要的字体、照片、布局及关键动画初始化。

这些资源的准备状态决定 Loading Ripple 的完成进度。

**后续资源（Deferred）**

包括后续图片集、Journal 及非首屏功能。

它们不应阻止 Prelude 进入完成状态。

### 12.2 加载进度计算

浏览器没有天然统一的整个网站加载百分比。

因此，必须建立明确的关键资源任务清单。

加载进度应依据实际任务完成情况计算。

可以按资源类型设置合理权重，但权重需与实际准备工作相对应。

不允许通过固定定时器虚构百分比。

### 12.3 加载进度的基本约束

- 实际进度保持单调不减。
- 视觉进度平滑追随实际进度。
- 进度达到 100% 代表所有规定的关键任务均已完成或安全降级。
- 不能出现加载失败导致进度永久停滞。
- 不因非关键资源延迟而延长等待。

### 12.4 快速加载与缓存

对于资源已缓存、首屏快速就绪的情况，允许省略明显的 Loading Ripple 过程。

避免仅为播放动画而人为增加等待时间。

### 12.5 加载异常

如果部分关键照片加载失败，可使用可用的替代资源或降级构图。

如果品牌字体加载失败，可以启用字体回退。

如果动画系统初始化失败，应允许直接进入可访问的静态首屏。

不能因为 Prelude 自身的脚本错误，让用户永久停留在等待页面。

### 12.6 最小依赖原则

Prelude 的启动界面应尽量减少外部资源依赖。

同心圆绘制及最小状态控制不应等待全部网站脚本执行完毕才能显示。

---

## 13. 响应式与可访问性

### 13.1 桌面端

以 PPT 的 1920 × 1080 构图为主要基准。

保持圆环中心、品牌文字和整体留白关系。

### 13.2 移动端

允许重新调整圆环尺寸与构图。

应单独验证圆环是否允许部分超出屏幕边界。

不得造成非预期横向滚动。

### 13.3 减少动态效果

启用 `prefers-reduced-motion` 时：

- 禁用或明显弱化持续呼吸。
- 禁用交互涟漪。
- 使用简化的加载状态反馈。
- 简化复杂的圆环路径变形。
- 保留正常页面导航。

### 13.4 可访问性

品牌文字保留真实文本语义。

同心圆作为装饰元素不向屏幕阅读器重复提供信息。

加载状态可以通过可访问的状态文本表达，不应仅依赖圆环形态让用户判断进度。

## 14. 技术实现建议

### 14.1 技术候选

- HTML / CSS：页面结构与文字。
- SVG：同心圆及曲线形态。
- JavaScript：关键资源进度统计。
- GSAP：动画时间线。
- ScrollTrigger：滚动控制。

具体动画库及实现细节在技术验证阶段确定。

### 14.2 模块划分

建议将 Prelude 拆分为以下逻辑单元：

| 模块 | 职责 |
|---|---|
| Resource Loader | 首屏关键资源准备与进度计算 |
| Loading Ripple | 加载进度到涟漪振幅的映射 |
| Prelude State | 动画状态管理 |
| Ring Renderer | 同心圆及几何形态 |
| Brand Transition | Pebril / 溪石交替与归位 |
| Interaction Controller | 鼠标与触摸反馈 |
| Scroll Controller | 退出及反向滚动 |

### 14.3 动画控制原则

加载涟漪、交互涟漪和呼吸效果可以共享圆环渲染系统，但必须区分状态来源。

不得让多个独立动画同时竞争控制同一个几何属性。

P4 开始后，应由滚动时间线接管圆环的主要几何状态。

### 14.4 性能要求

持续涟漪和呼吸应控制绘制成本。

优先避免频繁触发布局计算。

动画性能须在桌面和移动端实际验证。

## 16. 已确认事项与待验证事项

2. 初始构图为中央品牌文字与三个同心圆。
3. P0 为约 1 秒的初始浮现动画。

10. 三个圆环从外到内依次在顶部断开。
11. 三个圆环最终汇聚为唯一的水平直线。
12. 直线向下移动并逐渐淡出。
13. 该直线为后续时间轴提供视觉伏笔。
14. 「溪石」在退场时隐藏，Pebril 移动至导航栏中央。

## 17. 设计结语

Prelude 不只是一段等待动画。

它是 Pebril 视觉叙事的起点。

用户打开网页时，三个同心圆从暖白色的画面中逐渐浮现。

此时，资源仍在准备，圆环上存在轻微的涟漪。

随着加载进度不断提高，波动逐渐减弱，水面慢慢恢复平静。

当页面准备完成，Pebril 渐隐，「溪石」浮现。

同心圆开始轻轻呼吸，安静地等待用户的下一步探索。

当用户向下滚动，三个圆环依次从顶部断开、展开，并最终汇聚为唯一一条直线。

线条逐渐向画面底部移动并消散。

Pebril 回到导航栏，正式的相册扉页随之显现。

而那条曾经由涟漪形成的直线，将在后续时间漫游中，以时间轴的形式重新出现。

**波动 → 平静 → 呼吸 → 归线 → 时间。**

这一过程表达了 Pebril 对记忆、时间与秩序之间关系的理解。

**从流动中发现联系，在秩序中保留自由。**
