## 资料权威与范围

官网设计的当前依据是用户提供的《Pebril 预发布官网设计白皮书》v0.3。本 Wiki 按主题完整拆分该原文，保留原有确定、候选与待验证的区别。

产品理念来自产品仓库的 `docs/design-philosophy.md`。Wiki 中四篇英文页面是阅读快照；开发仓库的维护原文及其产品规范、计划和 API 合同继续决定技术交付范围。这里不另建技术规范或发布计划。

若白皮书与产品愿景在范围、时间或技术状态上出现差异，应记录具体差异并核对维护规范，不将愿景升级为发布承诺。本次没有把旧原型能力或早期聊天建议混入白皮书正文。

## 每项规则维护一个位置

- 品牌文案在“品牌与文案”维护，字体与候选色值在“视觉基准”维护。
- 照片露出、密度与包络在“首屏与照片布局”维护。
- 六阶段顺序在“滚动分镜”维护；归集细则在“春雨归集”维护；页脚动效在“柳梢与溪流”维护。
- 时间坐标、标签与聚焦行为在“时间轴探索”维护。
- 共享实现原则在“设计系统”维护；跨视口与无障碍要求在“响应式与可访问性”维护。
- “设计状态”是状态索引。设计状态变化时，同步修改相关主题页，索引用链接引用细则。

原文在分镜、细则和状态总结中有必要的重复。本轮保留其内容；后续更新详细规则时先更新主题细则，再检查分镜与状态摘要的一致性，避免三个位置出现不同参数。

## 设计状态的用法

| 状态 | 含义 |
|---|---|
| 已确定原则 | 已形成设计基准；不等于完成实现或通过验收 |
| 候选方案 | 尚未冻结的颜色、技术选型或实现方式 |
| 原型起点 | 用于实验的数值或范围，可以依据验证调整 |
| 待验证 | 需要原型、实机或数据语义核对后作出决定 |
| 长期愿景 | 产品方向，不能作为本轮交付要求 |
| 历史归档 | 仅用于追溯，不再作为当前规则 |

例如“平均 2–4 秒微动”是原型起点，不能改写为固定节拍；五张是前景预览上限，不是图片集容量限制。

## 日常修改流程

1. 从首页找到主题页，直接修改对应规则，避免再追加一篇重复白皮书。
2. 保留“候选”“约”“待验证”等限定；状态变更时写明依据。
3. 检查关联页面与状态索引；新增或改名页面时更新首页、来源映射和链接。
4. 在变更记录中写明日期、改动页面、决定及验证依据。纯错字修订可简记。
5. 来源快照和历史稿保持不变。再次接收新版白皮书时保存新版本快照，再逐项合并，避免覆盖历史来源。

Wiki 是本地 Markdown 文件集，可用支持 Markdown 的编辑器浏览与维护；未部署独立 Wiki 服务，也没有引入额外运行依赖。
