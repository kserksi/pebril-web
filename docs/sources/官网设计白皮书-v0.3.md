01. 项目定位

Pebril（中文候选名称：溪石）是一个正在开发中的个人照片整理与时间探索项目。

它通过时间轴、图片集和用户自定义标签，使照片能够按照真实的时间信息被浏览，也能够依据用户赋予的意义建立新的联系。

预发布官网承担品牌介绍、产品体验和公开开发记录三项职责。

网站由以下部分构成：

Home /：品牌叙事、照片河流、滚动动画、交互式时间轴演示。

Journal /journal/：设计思考、开发记录、技术文章与项目进展。

Journal Article /journal/[slug]/：独立的文章详情页。

首页为连续滚动的单页，不采用依赖完整 SPA 才能呈现内容的结构。

02. 核心设计哲学

Quietly Present.

静静存在，恰如其分。

Pebril 的界面应当在理性与感性之间保持平衡。

理性来自准确的结构、清晰的时间关系和一致的交互规则。

感性主要来自用户自己的照片、时间与记忆。

品牌情绪以杜甫《春夜喜雨》中的意境为参考：

随风潜入夜，润物细无声。

这一意境通过色彩、留白、运动节奏和交互反馈体现，而不需要具象的雨滴、花朵或自然装饰。

核心原则：

照片是情绪主体，界面不与其争夺注意力。

动画服务于产品叙事，不以炫技为目的。

用户始终掌握浏览与探索节奏。

视觉状态之间保持连续性。

保持清晰的产品信息与内容可访问性。

把独立开发者的实现与长期维护成本作为设计约束，避免没有明确价值的重复方案。

04. 视觉设计基准

4.1 标准画布

桌面端标准设计基准为：

1920 × 1080，16:9。

六阶段主分镜以这一画布作为初始设计参考。1920 × 1080 不是实际网页的固定尺寸，也不是要求所有屏幕维持 16:9 的画面比例。

实际网页根据视口和容器的可用尺寸连续自适应。统一视觉构图、品牌层级和叙事逻辑，不为桌面、平板、手机、折叠屏或超宽屏单独维护完整页面和动画版本。

设计目标是保持跨屏幕的视觉一致性，而非机械缩小整页。必要时允许局部调整留白、照片可见密度、时间刻度密度与交互控件排列，但不因此改变核心构图语言。详细规则见第 13 章。

6.2 照片的初始状态与河流动效

初始状态采用半隐藏、低焦点的照片呈现方式。

用户尚未主动探索时，照片只在首屏底部隐约显现；品牌、Slogan 与介绍文字仍是视觉焦点。

空间与可见性

照片以高低错落、轻微角度差与局部层叠形成底部带状分布，不排列成机械整齐的栅格。

半隐藏主要由位置与视口底部裁切实现：不同照片从画面下缘露出的比例不同，部分卡片延伸至视口之外；不以整体降低透明度作为主要手段。

照片不遮挡主文案，不产生强烈的单张焦点；构图与裁切应随容器空间连续自适应。

露出层级与空间密度（v0.3 动效补充）

照片河流以三个视觉露出层级组织底部构图。这里的“层”描述露出深浅与视觉层次，不要求排成三条整齐的横行，也不预设固定的 DOM 或 z-index 分层。

视觉层级

单张照片可见高度占完整照片高度的比例

设计含义

底层 · 较明显

不超过 50%

提供底部河流的主要存在感，但照片仍处于半隐藏状态

中层 · 较隐约

约 25%，原则上不超过 25%

形成由明显到隐约的过渡

高层 · 最克制

不超过 15%

只留下微弱的视觉暗示，不抢占品牌文案注意力

露出比例指照片经视口底部裁切后，实际可见高度占该照片完整高度的比例，不以降低透明度代替裁切。这些数值是当前原型的设计目标与上限，不是要求每张图片恰好露出指定比例；高低错落和尺寸差异仍需自然。

相邻照片的密度控制以主流动方向上的排列关系为基准：

重叠：常规建议约 20%–35%；局部较密区域可以接近 40%；考虑个体微动后的实际状态，原则上不超过 50%。

间隔：相邻照片常规建议保持在参考照片宽度的 10%–30%；较疏处可延伸至 40%；动态过程中的最大间隔原则上不超过参考照片宽度的 50%，避免视觉断流。

度量口径：上述百分比在首轮原型中按主流动方向（通常是水平轴）的投影计算；重叠量以两张照片投影宽度中较小者归一化，正间距也以这一参考宽度归一化。实际遮挡面积、旋转后的视觉拥挤程度另行验收，不将水平投影比例误作遮挡面积比例。

动态安全余量：静态初始排布宜更保守，重叠可先控制在约 15%–30%、间隔约 10%–25%，为上下浮动、轻微旋转与相对速度差留出余量；运行中不应出现明显碰撞、局部遮挡突增或断流。

以上数值基于首轮设计判断，用于约束画面感受，而非固定所有视口的坐标。实现时可随容器空间调整可见照片数量、尺寸与分布；如窄屏确实无法同时满足这些建议区间，应优先保证文案可读、连续流动、视觉不拥挤，再在原型验证后调整局部约束，不单独维护一套设备专属动画。

运动语言：溪流主导，落叶响应

整体主运动：照片沿同一个方向持续、缓慢流动，具有共同的流向，如同被同一股溪水带动。

个体副运动：每张照片在主运动上叠加幅度很小、彼此不同的上下浮动、轻微角度摆动及细微的速度或相位差，呈现水面落叶般的自然状态。

个体微动采用受约束的自然变化：变化应连续、低频、平缓，避免逐帧无规则跳变；随机感不等于完全无序。

主运动始终强于副运动。个体差异不得破坏整体单向缓流的秩序，也不应演变成悬浮弹窗、粒子飞舞或机械跑马灯。

运动应连续且不出现可察觉的循环重置；不使用明显的闪烁、弹跳、发光、突然反向或大幅旋转。

首屏应让用户先理解品牌，再逐渐察觉照片正在流动。不是让动画主动吸引注意，而是让流动被自然发现。

本节的露出比例、重叠和间距已作为首轮设计目标写明，但仍须经过关键帧分镜和真实视口验证；具体流速、微动振幅、相位差、照片尺寸与布局坐标暂不冻结为固定数值。

6.3 Fluid Photo Envelope — 弹性照片包络空间（v0.3）

固定的是共享空间约束，而不是每张照片的像素尺寸或宽高比。 Pebril 的照片河流采用相对面积目标与容器边界组成的弹性布局：每张照片保留自己的真实矩形轮廓，但在同一场景中具有相近、不过分突兀的视觉重量。

素材与实际显示

网站示例图片：由项目方预先选定，原始素材统一使用 1920 × 1080（16:9）；该分辨率是图片素材规格，不是网页中照片卡片的固定尺寸，展示时按容器计算尺寸并提供适当的响应式缩略资源。

用户本地图片：允许横图、竖图、方图及其他宽高比；按原始宽高比等比缩放，不强制转换成 16:9，也不为填满统一矩形而裁切或拉伸。

卡片轮廓：实际可见照片卡片跟随图片真实宽高比；不强制展示统一 16:9 背景框，因此不因图片比例不同产生明显的内部留白或黑边。

相对空间与视觉面积

以照片河流的场景容器为布局参照，定义每张照片的目标视觉面积、最大宽高、活动范围与文案安全区域；包络空间是不可见的布局约束，不是必须填满的可见卡片。

对常见比例照片，以接近的目标面积保持视觉均衡：横图相对宽而低，竖图相对窄而高，方图居中；允许轻微大小差异，避免机械一致。

目标面积上下约 ±15% 仅作为首轮原型的实验范围，不是正式冻结的性能指标或硬性容差。面积相近不意味着照片的感知显著性必然相等，仍需观察内容、对比度与可见部分的效果。

极端宽幅、细长竖图或其他特殊比例可能无法同时满足面积目标和最大尺寸约束。此时优先保证比例真实、不遮挡文案、不越过安全边界、不造成局部拥挤，允许面积偏离目标；需要时可在交互中单独查看完整照片。

容器与图片尺寸变化后，布局应根据实际卡片边界重新确定间距、重叠与运动锚点。第 6.2 节规定的 50% / 25% / 15% 露出层级，应按各张卡片自身的完整高度计算，同时受统一的首屏文案安全区域限制；重叠与间距按照第 6.2 节的水平投影度量口径执行。

实现取向与运动连续性

采用统一的 PhotoCard 行为与布局规则，不为横图、竖图、方图分别维护独立组件和整套动画；具体组件命名仍为实现候选。

优先利用容器查询、相对尺寸单位、clamp()、aspect-ratio 等现代 CSS 能力描述弹性边界；对于需要错落、层叠与汇聚的河流场景，可由统一布局计算决定位置，再使用变换执行运动，不把普通 Flex/Grid 的自动排布当作完整动效算法。

图片宽高比、数量或视口变化后，应平稳更新卡片尺寸与运动锚点，保留一套六阶段滚动叙事和统一 Motion Tokens；按内容失效点做局部处理，不建立设备专属或图片比例专属的独立动画版本。

以上原则已确立；面积计算方式、最小与最大卡片尺寸、尺寸分布、极端宽高比阈值与动画重排策略仍需在原型中验证。

07. Memory in Motion：滚动叙事

7.1 动效定义

Memory in Motion — 流动的记忆

这是 Pebril 首页最重要的视觉交互。

同一批照片从第一屏的自由流动状态，先随下滑由半隐藏逐渐完整显现，再以「春雨成河」的方式逐张汇入局部集合、凝聚为图片集，最终与第二屏的时间轴共同形成稳定的时间秩序。

整个过程由用户滚动主导。

动画支持正向和反向变化，不以固定时长强制播放。

7.2 六阶段分镜

Phase 0 · Quiet Flow

首屏初始状态：半隐藏的记忆

品牌、Slogan 与介绍文字占据视觉中心。

照片在首屏底部高低错落、由视口下缘自然裁切；三个视觉露出层级以 50% / 约 25% / 15% 为当前上限与参考目标，具体定义见第 6.2 节。

照片没有明显的个体焦点，品牌文案保持视觉优先级。

照片显示尺寸由弹性包络空间约束；不同原始比例保留各自轮廓和接近的视觉重量，不强制统一 16:9 卡片。

图片河流整体同向缓流，各照片叠加轻微、连续且受约束的个体微动，如同溪水中的落叶。

时间轴尚未出现。

情绪关键词：隐约、安静、流动。

Phase 1 · Gentle Gathering

用户开始下滑：先完整显现，再自然汇聚

首屏文字轻微上移或淡出，底部半隐藏的照片随下滑逐渐进入更多可见区域。

整条照片河流充分、完整显现后，用户继续下滑，才开始照片归集；不在照片尚未被看清时提前整体收束。

自主流动平滑让位于滚动进度控制，避免照片跳回预设起点、突然停顿或突兀转向。

每个图片集先选定代表主图；主图率先从当前视觉位置沿柔和曲线缓慢下移，并逐渐缩小，带出局部汇聚方向。

运动隐喻由首屏「溪流中的落叶」过渡为「春雨逐滴归点」。先前的花朵式柔和弧线可以作为路径参考，但不形成具象花朵或雨滴。

情绪关键词：显现、靠近、牵引、自然。

Phase 2 · Gentle Alignment

照片逐张归集：图片集凝聚成形

主图下移，与邻近照片形成约 20% 的遮盖关系时，第二张开始移动；随后第三、第四、第五张依次加入。20% 为当前视觉目标，实际测量口径和容差留待原型验证。

照片在位移过程中逐渐缩小、减小旋转幅度，最终形成最多五张清晰前景图的轻微扇形层叠，而非完全重合或夸张扑克牌扇面。

当第二、第三张开始归集、图片集轮廓初步成立时，象征集合中其余照片的少量弱化后景层从前景后方缓慢浮现，在第五张归位前后完成视觉深度；优先使用层叠与低对比度，需要时使用克制的模糊。

五张仅是可见预览上限，不是图片集的实际容量上限。不足五张则展示实际数量；更多照片仍属于图片集，不要求每张都作为独立的后景卡片渲染。

多个图片集可以轻微错峰凝聚，但属于同一连续滚动叙事；时间轴在图片集逐步成形时就开始缓慢显现，不等待所有图片集完全形成。

保留「卡牌式整序」的轻微叠放与对齐规律，但整体以「春雨凝聚成集」为主导意象，不形成水滴实体、碰撞效果或机械排队动画。

情绪关键词：逐滴、凝聚、层叠、归整。

Phase 3 · Timeline Reveal

第二屏成立：图片集与时间轴同步稳定

时间轴在画面中部、相对固定的布局锚点上逐渐增加可见度，不从边缘飞入，也不大幅移动或缩放。

图片集沿各自轨迹逐渐下移并停在时间轴上方，与相应的真实时间位置对齐，保留恰当的呼吸空间，不与时间轴发生视觉碰撞或弹跳。

时间轴显现与图片集归位共享滚动进度并部分重叠进行：图片在形成秩序的同时，承载它们的时间结构也逐渐清晰；不是先完成其一、再播放另一段。

时间刻度、集合与时间位置的对应关系，以及第二屏标题与提示，随后轻柔补足；稳定状态可直接进入时间轴交互。

最终默认不绘制图片集到时间轴的常驻连接线，依靠空间对齐表达关系；仅在明确聚焦或选中时显示辅助关联，见第 8.3 节。

时间轴应呈现一种「它原本就在这里，只是现在被看见」的感觉。

参考克制的 Apple 式产品展示节奏，但保持 Pebril 自己的视觉语言。

情绪关键词：显现、稳定、精确。

Phase 4 · Quiet Dissolution

继续下滑：从图片集释放为河流

第二屏先保留足够的稳定浏览空间；用户继续下滑时，图片集解除轻微扇形层叠，前景照片逐渐恢复为具有不同轮廓和姿态的独立照片。

后景弱化层逐渐退去，独立照片重新形成与第一屏呼应的同向缓流；不完整倒放「春雨成河」的逐张归集过程。

河流以横向流动为主、轻微向上舒展为辅，逐步释放页脚上方的留白。大多数照片沿原有流向渐次离场，不突然飞散或集体淡没。

每个图片集的前三张代表照片保留为更松散的局部残留群组（实际不足三张时按真实张数），不继续保持完整图片集结构；它们在原时间位置附近留下视觉余韵，形态联想到柳树末梢的嫩芽，而非组成具象水纹。

时间轴的刻度、标签和交互强调逐渐减弱，主体线条保留平稳的空间锚点，缓缓过渡为页脚上方一条低振幅、长波长的柔和波浪分隔线。

退场的主要动作仍由滚动位置统一控制、可逆；时间轴与页脚之间为视觉连续关系，不强制将时间轴所有子元素变形为页脚组件。具体实现见第 7.4 节。

情绪关键词：松开、回流、舒展、留痕。

Phase 5 · Quiet Closure

页脚出现：柳梢与溪流的安静余韵

页脚品牌名称、Slogan 和 Journal、GitHub、X 等链接在稳定留白中轻柔浮现，不再制造新的动画高潮。

上方保留的少量照片群组近乎静止，像柳梢末端的嫩芽，只在合适时机发生微弱、非持续的自然扰动。

下方波浪线兼作最后一屏与页脚之间的结构分隔；在少量局部位置，对上方照片的微动或用户交互作出不完全同步、具有差时与衰减的涟漪回应。

用户明确点击、触控或键盘激活时，应得到及时且可感知的反馈；非主动状态允许长时间安静，不要求照片每次微动都触发波纹。

波浪线和照片的联动不应妨碍阅读、链接点击、焦点可见性及页面滚动；系统减少动态效果设置下应采用静态或显著简化呈现。

整个页面最终不是绝对静止，而是静中有动、动而不扰，让「时间仍在向前、记忆仍有回响」留在页脚上方。

情绪关键词：平静、回响、留白、余韵。

7.3 Spring Rain to River — 春雨成河：归集关键帧与数据边界（v0.3 动效补充）

核心意象：「随风潜入夜，润物细无声」。照片像春雨一样逐滴归入局部汇聚点，逐渐凝聚成一个又一个图片集；时间轴像稳定的河道，在它们归位时缓慢显现。借用自然汇聚的节奏，不直接绘制雨滴、水纹或河流特效。

图片集的实际内容与可见预览

集合成员数与预览张数分离：图片集可包含多于五张照片；前景最多五张，以轻微扇形错位体现多图关系；实际少于五张时不复制照片凑数。

后景只表达深度：由少量柔和、低对比度或轻度模糊的层次暗示其余内容，而非把全部剩余照片逐张渲染；可以呈现真实数量信息，不以弱化卡片数量冒充实际总数。

自然运动不篡改真实归属：照片所属集合、可信拍摄时间与时间轴位置由真实数据语义决定。随机性只用于主图展示选择、微小视觉差异和可复现的运动编排，不应把空间相邻但数据无关联的照片误归为同一个集合。

滚动绑定：共享归一化滚动位置作为进度源，因此慢滚、快滚、暂停、反向滚动均对应同一组可恢复的空间状态；滚动速度影响进度推进快慢，不单独通过瞬时速度触发不可逆的排队动画。

轻量化优先：无需通过复杂实时模糊、为每个隐藏成员创建卡片或大量同时运行的图层来证明集合深度；应在性能和可访问性验证中决定后景层的实现细节。

仍待原型验证

约 20% 遮盖的实际计算口径（投影还是可见面积）、第三至第五张的具体启动间隔、各集合的错峰尺度、卡片的扇形角度、后景层的数量与模糊程度、归位路径、时间轴的细节显现区间及滚动区间长度，均为未冻结参数。

7.4 Willow & Stream — 柳梢与溪流：退场余韵及分级反馈（v0.3 动效补充）

**核心意象：**退场后保留的少量照片如春雨中柳树枝梢末端的嫩芽，下方由时间轴演化而来的波浪分隔线如柳树下的小河。照片并不被裁成柳叶，也不绘制鸟、柳树或雨滴；使用微小位移、角度变化与局部波纹表达自然的影响关系。上方微动可以引起下方响应，但并非一动必有波。

空间与状态

退场先解除图片集、恢复同向缓流，之后逐渐散开、轻微上扬并远去；各图片集前三张代表照片（不足三张时按实际）成为局部残留群组，具体可见密度按容器与视口调整。

残留照片保持真实矩形轮廓、轻微错落和松散关系，不形成机械弧形阵列；它们代表余韵，不是原图片集容量的缩减或永久删减。

波浪线由时间轴主轴连续演化而来，保留分隔页脚的结构职责。低振幅、长波长、较低对比度是默认状态，不把整条线做成持续同步的装饰水波。

主动滚动转场阶段优先由统一滚动进度决定空间状态；到达稳定页脚区后才允许环境微动接管，避免滚动逆向恢复时发生跳变或无法复现的布局状态。

差时、自然性与交互优先级

不做机械的一比一映射：照片微动是可能的扰动来源，不是每次都要同步驱动波浪；环境事件允许错峰、随机但受约束的间隔，也允许完全静默。

主动交互必须可感知：点击、触控明确激活及键盘激活应有及时反馈，不采用随机概率丢弃明确操作。波纹从当前群组下方的局部位置扩散，并在照片回稳后留下适度余韵。

轻交互不得争夺滚动：鼠标 Hover 或轻掠可作为清风触发；触屏上不得仅靠 Hover，轻滑识别不能截获用户正常纵向滚动或与时间轴的主要手势冲突。装饰反馈不能取代真实点击、选择或焦点行为。

波纹遵循局部与衰减：不同时刻、不同群组对应的波峰有差时和相位差；影响以邻近线段为主，向两侧轻微传递后衰减，不驱动整条横线一起抖动。

克制优于次数：平均 2–4 秒不是必须严格执行的节拍器；允许更长静默和因可见性、设备性能、用户设置而减少或停止自主动画。不使用持续每秒两三次的常态抖动。

可访问性优先：支持 prefers-reduced-motion 的静态或大幅简化替代；键盘、触控、鼠标均可获得必要交互反馈，波纹本身不是唯一的信息传递方式，页脚文字与链接始终稳定可读。

待验证的量化参数

微动平均间隔与内部节奏、不同互动等级的位移/旋转幅度、Breeze 与 Bird Pass 的响应延迟、波纹振幅与波长、局部影响范围、传播与余韵衰减时长、多个群组同时交互时的叠加上限，以及低性能设备和减少动态效果场景下的回退规则，均通过原型与实机测试确定。不提前把诗意隐喻转化为具象的特效或复杂物理模拟。

7.5 关于转场力度

正式采用以下区分：

前半段负责显现，后半段负责收束。

第一屏到第二屏可以使用较完整的照片汇聚、归整与时间轴显现过程。

第二屏到页脚不应继续制造同等强度的视觉表演。

用户最应该记住的是时间轴的出现与产品体验，而不是页脚动画。

7.6 滚动行为

滚动动画必须满足：

进度由用户的滚动位置决定。

允许反向滚动恢复之前的状态。

停止滚动时，滚动叙事的构图与关键位置保持稳定；第 7.4 节的页脚常态微动属于独立且受约束的余韵层，不推进滚动叙事进度。

不强制自动播放整段转场。

不通过长时间锁定滚动妨碍阅读。

自主照片运动与滚动控制不会发生冲突；进入或退出滚动叙事时，照片位置与速度感应连续衔接，避免突兀跳变。

不同视口共享同一套六阶段状态与滚动进度模型；动画坐标应优先基于场景容器及其锚点计算，不依赖单一固定像素画布。

视口变化时可以调整运动距离、图片密度与必要布局约束，但不维护独立的设备专属叙事实现。

具体滚动区间、缓动曲线、移动路径与时间比例，留待正式分镜和原型验证。

08. 第二屏：时间漫游

8.1 第二屏稳定状态

第二屏最终呈现完整的时间漫游演示。

其主要结构为：

顶部简洁的产品理念文案。

位于视觉中部、位置相对固定的时间轴。

位于时间轴上方的图片集。

必要的交互提示与本地照片演示入口。

第二屏不能只是一张动画结束后的静态截图。

它需要允许用户进行有限但真实的探索。

8.2 时间轴显现方式

时间轴以透明度、轻微对比度和结构细节逐渐显现。

不使用明显的飞入、弹跳或剧烈缩放。

时间轴在转场期间保持稳定视觉锚点。

图片集向时间轴对应位置移动，而不是让整条时间轴追逐图片集。

图片集归位与时间轴主体的淡入同时发生并逐渐收束；时间轴的线条、刻度可以分层补足，但不能等图片集全部完成才开始出现。两者在视觉上保持稳定的空间锚点与呼吸距离，不以碰撞、弹跳或明显的形态变换表现「承托」。

8.3 图片集与时间轴的关联反馈（v0.3 动效补充）

默认状态：图片集按其真实时间关系排列在时间轴上方，通过位置及刻度对齐建立联系；不绘制常驻连接线，避免增加视觉噪声。

聚焦状态：在鼠标悬停、键盘焦点进入、触控点击选中或其他明确聚焦操作时，当前图片集到对应时间位置之间可以轻柔淡入一条纤细的辅助连接线，并适度强调相应刻度；不得产生明显放大、弹跳或抢夺注意力的效果。

退出与可访问性：悬停结束或取消选中后，辅助线平稳淡出；触屏与键盘必须能获得等价反馈。时间关系应同时提供可读的时间信息，不能仅靠线条或颜色表达。

与滚动叙事协调：进入第二屏稳定交互状态后，关联线属于用户主动探索的反馈，不参与此前的春雨汇聚主动画；避免细微滚动打断当前聚焦操作。

8.4 交互优先权

当用户开始与第二屏的时间轴、图片集或标签发生明确交互时，应优先保证交互稳定。

不应因为细微滚动或鼠标移动，使当前操作中的图片集突然重新进入转场动画。

具体处理方式，例如交互区域的稳定滚动区间、焦点转移及退出逻辑，后续在交互设计阶段确定。

8.5 时间标签基本规则

时间标签属于用户创建的独立标签体系。

时间标签的覆盖区间与照片原始拍摄时间、上传时间之间保持概念与数据上的独立。

选择时间标签不会改变照片的原始时间坐标。

多时间标签选择采用 OR 匹配：图片集只要匹配任一已选标签即可保持正常展示。

用户定义的标签颜色独立于品牌配色。

时间轴上的多标签重叠、Focused 标签及相关探索行为继续遵循此前确定的 Pebril 产品交互规范。

09. 本地照片演示

预发布首页提供以浏览器本地处理为原则的照片演示能力。用户通过文件选择或拖入方式，临时使用自己的照片体验 Pebril 的照片河流、汇聚整序与时间轴；这里的“上传”是界面上的选取动作，不表示照片被发送到服务器。

9.1 Photo Source Independence — 图片来源与展示、运动解耦

默认显示项目方预选的 1920 × 1080（16:9）网站示例素材；用户选择本地照片后，将当前展示数据源切换为用户照片，并可随时恢复默认素材。

替换的是照片数据，不是运动系统：默认示例图与本地图片共用第 6.3 节的弹性卡片、空间约束和同一套六阶段 Memory in Motion 叙事，不创建示例图与上传图各自独立的页面和动画版本。

同一份当前照片集合供首屏河流与第二屏时间轴使用。照片数据至少应包含临时身份标识、图像来源、可用尺寸与宽高比、可信时间信息（如有）；切换数据源时，时间轴和图片集位置随对应时间数据一起更新，不允许仅替换像素、继续沿用示例图片的虚构时间坐标。

本地照片同样保留原始宽高比，并受统一的视觉面积与最大宽高约束；不使用可见的固定比例外框来制造留白。

数据源切换应在图片准备可用后进行，尽量采用克制的过渡或平稳重排，避免正在浏览或操作时间轴时出现清空、闪烁和突兀跳变；具体交互时机仍待原型验证。

9.2 本地处理与生命周期

用户图片只在浏览器本地读取、解析和展示，不上传服务器，不要求注册，不建立云端存储，也不修改原始照片文件。

当前默认采用页面会话内存态：本次页面打开期间保留用户选择的照片；刷新、关闭后可恢复网站默认示例集，不承诺跨访问持久化，也不主动保存到 localStorage、IndexedDB 或后台。

提供“恢复默认示例图”与“清除当前本地照片”能力，并及时释放不再使用的临时预览资源。

界面必须明确提示照片仅在本地处理、不会上传，以及何时会清除；不将浏览器临时预览描述成持久安全存储。

照片拍摄时间优先来自可可靠解析的本地元数据；未知时间需明确标记或单独处理，不得为了视觉效果虚构时间，也不修改照片原始时间信息。

具体可接受的文件格式、单次数量、体积限制、浏览器内解析与解码策略、极端图片比例处理、失败提示及数据替换过渡仍待技术与原型验证。

10. 统一设计系统

Pebril 采用 Single Source of Truth（单一事实来源） 原则，并将 One System, Adaptive Everywhere（一套系统，自适应呈现） 作为响应式实现目标。

每项共享规则、资源和行为应当只有一个权威定义位置。 全站颜色、字体、间距、圆角、阴影、动画参数和响应式约束通过集中化设计 Token 或相应共享模块管理。修改公共参数后，其依赖组件应自动获得更新，避免跨页面复制和手动同步。

这并不意味着所有配置、组件和业务逻辑都必须塞进同一个文件，或保证任何功能改动仅涉及一个文件；真正追求的是修改一项公共规则时，只修改它的权威定义。

10.4 资源与组件的唯一权威来源（v0.3）

品牌颜色与排版：在统一 Token 定义中维护颜色角色、字体角色、尺寸与间距，不在各页面重复写死相同数值。

图标与静态素材：共享同一套权威资源及引用方式；优先使用 SVG 表达标识与线性图形，照片按需采用适宜的位图格式。

照片河流与时间轴：PhotoRiver、PhotoCard、Timeline 等仅作为建议的共享组件边界，不预设已实现或必须采用这些文件名；相同用途不按设备型号或照片比例复制独立组件。照片来源与尺寸计算、空间布局、运动执行分离；共享弹性包络和六阶段叙事的权威定义。

动效与响应式布局：共享六阶段状态机、进度模型与 Motion Tokens；布局计算和动画执行可以分别封装，但引用同一组语义参数。

官网与 Journal：尽量复用基础视觉系统，允许阅读型页面避免首页特有的复杂运动。

公共配置应维持清晰的职责边界。颜色、字体、布局、动效等可以分模块存储并由统一入口提供，不建立难以理解和修改的巨型配置文件。

10.5 维护成本与新增抽象的判定（v0.3）

Pebril 目前主要由一位开发者维护。实现新设计或特殊适配时，先确认是否能够通过现有布局约束、共享组件或统一参数完成；再衡量新增复杂度是否带来真实可感知的价值。

不因为设备种类多而创建多套完整页面，也不为微弱视觉差异引入长期重复维护的动画实现。确有交互、可访问性或性能问题时，可以进行局部例外处理，但例外应保持可测试、可解释且范围尽可能小。

11. Journal 设计

Journal 是 Pebril 的公开开发手记空间。

内容包括产品设计、开发过程、技术实现、交互探索、版本变化和重大设计决策。

Journal 共享品牌颜色和字体系统，但更加注重长篇阅读。

不引入首页的大规模滚动叙事动画。

文章允许自然出现英文技术名称、代码片段与命令，并采用规范的中英文混排方式。

中文导航可以使用「手记」，栏目名称仍保留 Pebril Journal。

公开文章需明确区分已经实现的功能、已确定的设计原则和仍在探索的构想。

官网的关键信息必须能够通过 HTML 直接读取，不依赖完整动画执行后才能显示。

基础措施包括：

准确的页面标题和描述。

Canonical URL。

Open Graph 元数据。

XML Sitemap。

合理的结构化数据。

正确的文章时间与内部链接。

可访问的文本内容。

搜索引擎及适用 AI 搜索爬虫的抓取配置。

Journal 主要承担长期有价值内容的积累。

不虚构尚未发布的功能、用户评价或商业成果。

13. 性能、响应式与可访问性

13.1 Responsive by Composition — 构图自适应（v0.3）

采用一套设计、一套滚动叙事、连续自适应构图，并在真实需要时做局部处理的策略。

首页保持中央轴线、品牌主次关系、大面积留白、底部半隐藏照片河流及六阶段 Memory in Motion 叙事。不以屏幕宽窄为理由改造为不同的品牌页面，也不把完整 1920 × 1080 画面等比缩放到其他视口。

自适应的主要手段依次是：

流式布局与容器最大/最小尺寸约束。

弹性字号、间距和安全留白。

基于容器的相对坐标、锚点及运动边界。

按可用空间及照片原始宽高比调整弹性卡片的视觉面积、最大宽高、可见密度、图片集分布和时间刻度密度。

当以上方式不足以解决真实问题时，采用少量基于内容失效点的局部断点。

不按设备名称设置产品级版本。 同一套组件和核心逻辑应能够在桌面、平板、手机、折叠屏和超宽屏持续工作。

13.2 非典型视口与局部例外（v0.3）

窄屏：文字保持可读；照片允许由视口边缘裁切，但不能遮挡主要文案；弹性卡片可降低尺寸和可见数量，时间轴刻度可降低密度，操作入口必须可用。

矮屏：优先减小非必要垂直间距和背景元素占用，避免标题、图片集及时间轴重叠。

超宽屏：正文内容保持舒适的最大宽度；照片河流可向两侧自然延伸，不强制将全部内容拉宽。

折叠屏与变化的视口：按实际容器、窗口宽高比和可用空间计算，不预先为具体型号制作专属页面。

第二屏的时间轴可以针对触控、键盘及鼠标输入提供适当的局部操作适配，但应保留同一套可信时间坐标和交互语义。网页纵向滚动与时间轴的探索操作不得互相争抢。

13.4 性能原则

静态优先，按需加载客户端交互。

优化网站示例照片的响应式缩略资源；本地照片仅按展示需求进行浏览器内解码与预览，避免小卡片长期持有不必要的全尺寸渲染；延迟加载非首屏模块。

避免大量布局抖动；优先使用性能稳定的滚动动画属性及策略。

控制模糊、滤镜、长列表和持续运动造成的负载。

视口变化时平稳重新计算布局与动画锚点，避免突兀跳变。

监测真实设备上的交互流畅度，并将实际性能作为增加视觉复杂度的依据。

13.5 可访问性与减少动态效果

重要功能不得仅依赖鼠标 Hover；保证键盘焦点、触屏及鼠标等输入方式均能操作。

用户启用系统减少动态效果设置时，应提供简化或静态版本。核心产品信息、时间轴演示和 Journal 不应因为关闭动画而失去可访问性。

动画与适配的完整程度以真实测试和交互可用性为准，不以设备数量或视觉效果数量为绩效指标。

页脚用于收束品牌叙事。

主要包含：

Pebril / 溪石

以及 Journal、GitHub、X、必要隐私与法律信息。

页脚与时间轴的连接是视觉意象上的延续，而不是功能上将时间轴直接变成页脚。时间轴主体线条可以逐渐弱化为低振幅波浪分隔线；其上方少量残留照片与分隔线形成「柳梢与溪流」的局部、差时呼应（见第 7.4 节）。

16. 设计验收标准

首页原型应达到以下结果：

第一，安静。 用户初次进入页面时，文字清晰、照片运动微弱，不产生信息压力。

第二，连续。 照片从首屏到第二屏保留视觉身份，不发生突兀替换。

第三，稳定。 时间轴显现时保持相对固定；春雨式逐张归集、有限预览与后景弱化层逐渐组成图片集，并与时间轴同步建立秩序。

第四，可控。 用户能够自然滚动、反向浏览和交互，不被动画强制打断。

第五，真实。 时间标签、图片集成员数量与时间坐标的演示符合 Pebril 已确定的产品规则；五张仅为预览上限，视觉随机不得伪造归属或时间。

第六，克制。 页脚收束不应比时间轴显现更加引人注意；柳梢式残留照片、差时局部涟漪与低振幅波浪线需允许长期安静，不形成持续抖动或额外动画高潮。

第七，一致。 各屏幕共享颜色、字体、运动语言及设计原则，同时保持实际可用性。

第八，自适应。 不依赖设备专属整套页面，依靠统一构图规则覆盖常见与特殊视口。

第九，可维护。 共享参数与资源存在唯一权威定义，公共变更不要求同步修改多套重复实现。

第十，尊重照片。 不同比例的用户图片保持真实构图、无强制裁切拉伸及多余固定卡片留白；依靠相对面积与空间边界取得视觉均衡，并在源数据切换后保持动效和时间信息的一致性。

第十一，轻量关联。 第二屏默认靠位置与刻度传达图片集和时间轴的关系；悬停、键盘聚焦或触屏选中时才显现纤细辅助线，同时提供可读时间信息。

17. 结语

Pebril 的首页不是一段需要被完整观看的宣传动画。

它应当是一处安静的空间。

用户进入时，先看到一句话。

随后发现照片正在悄悄流动。

继续向下，照片逐渐靠近、归整，形成彼此关联的图片集。

时间轴慢慢浮现，照片找到自己的位置。

用户可以停下来探索，也可以继续向下，看着图片集轻轻松开、照片重新流动，大部分照片远去，少量照片如柳梢嫩芽般留在时间之河上。时间轴逐渐化为温柔的波浪线，在极轻的扰动与余韵之后，画面回归平静。

这一过程所表达的，不只是照片整理，而是 Pebril 对记忆、时间与秩序之间关系的理解。

从流动中发现联系，在秩序中保留自由。
